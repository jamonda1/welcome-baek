## 실제 브라우저 확인 상태와 제한

기존 Chrome의 백준 1001번 페이지에서 이전 버전의 분할·C++·Dracula 화면은 확인했다.
그 뒤 자동 조작 도구가 현재 브라우저 URL을 충분히 확실하게 판별할 수 없다고 작업을 중단했다.
따라서 **새 빌드를 Chrome에서 다시 로드하거나 저장·복원을 실기 검증하지 못했다**.
기존 확장 프로그램을 재등록하거나 사용자 초안을 지우지 않았다.

잔여 사항:

- 빌드 성공 시 `problem.js` 약 629.74kB(압축 전), 213.46kB(gzip)로 Vite의 500kB 경고가 있다.
  Content Script가 단독 일반 스크립트로 실행되도록 현재 묶음을 유지했다.
- 페이지가 숨겨지거나 이동할 때 저장을 시작하고, 미저장 데이터가 있으면 이동 경고를 요청한다.
  Chrome은 종료 시 비동기 작업 완료를 보장하지 않는다. 경고에서 강제로 나가거나 프로세스가 비정상 종료되면 마지막 미저장 입력까지 보장할 수 없다.
- 같은 문제·언어를 여러 탭에서 동시에 편집하면 마지막으로 성공한 저장이 남는다. 탭 간 병합이나 충돌 해결 UI는 없다.
- 용량 초과·API 오류 시 기존 저장본을 지우지 않고 초안을 현재 탭에 보존한다. 오류 안내에 따라 코드를 복사하고 재시도한다.
  저장 데이터 삭제·내보내기 UI는 이번 요청 범위에 포함하지 않았다.

Chrome Storage local의 기본 용량은 Chrome 114 이상에서 확장 프로그램 전체 10MB이며, 확장 프로그램 삭제 시 데이터가 지워진다.
별도 만료나 다른 PC로의 자동 동기화는 제공하지 않는다. `unlimitedStorage` 권한은 추가하지 않았다.
근거: [Chrome Storage 공식 문서](https://developer.chrome.com/docs/extensions/reference/api/storage).

## Chrome `D.of is not a function` 오류 수정 (2026-11-23)

실제 사용자 화면에서 재현된 초기화 오류를 수정했다. Chrome은 Content Script를 일반 스크립트로 실행하지만,
기존 빌드 결과는 ES 모듈의 엄격 모드를 가정하고 압축되어 있었다. 압축된 CodeMirror `ChangeSet`과
블록 내부 `flushAll` 함수가 모두 `D`가 되어, 비엄격 모드의 블록 함수 호이스팅으로 충돌했다.
이 예외가 초기화 과정의 오류 처리에 잡혀 ‘저장소 오류’로 표시되었다. 저장 공간 부족 오류가 아니었다.

`vite.config.ts`의 최종 산출물 생성 단계에서 `problem.js`를 엄격 모드 함수로 감싸도록 수정했다.
압축기가 엄격 모드 지시문을 제거하지 않도록 압축 완료 후 적용한다. 기존 팝업 빌드와 저장 데이터 형식은 유지했다.

`tests/bundle-runtime.test.ts`는 **실제 dist/problem.js를 일반 스크립트로 실행**한다.
수정 전에는 화면과 같은 `D.of is not a function`으로 실패했고, 수정 후 저장본 복원·언어 전환·수동 저장·최초 C++ 템플릿이 통과했다.
소스만 검사하던 기존 테스트의 사각지대를 보완했다. 전체 자동 테스트는 32개이며 타입 검사와 빌드도 통과했다.
최신 로그는 `phase4-typecheck.log`, `phase4-build.log`, `phase4-test.log`에 갱신했다.

적용: `chrome://extensions`에서 Welcome Baek 새로고침 → 백준 문제 페이지 새로고침.
확장 프로그램 제거·재설치나 저장소 초기화는 필요 없다. 실제 Chrome에서 수정본을 자동으로 다시 로드하지는 않았다.
